# 用户、客户与角色设计

## 设计结论

当前系统采用“客户是租户、用户是账号、角色决定操作范围”的模型：

- 客户负责数据隔离，知识库、会话、消息和 Agent Trace 都归属客户。
- 公开注册只创建客户用户，必须填写客户邀请码。
- 平台用户不走公开注册，只能由超级管理员在后台创建。
- 后台用户管理用于平台账号管理和客户用户补建，不替代邀请码注册链路。
- 数据查看按角色收口：内部角色看全平台，客户管理员看本客户，客户普通用户只看自己产生的历史。

## 角色边界

| 角色 | 归属客户 | 创建方式 | 主要权限 |
| --- | --- | --- | --- |
| `SUPER_ADMIN` | 否 | 后台创建 | 管理客户、邀请码和所有用户 |
| `PLATFORM_ADMIN` | 否 | 后台创建 | 内部运营/排障账号，可查看全平台业务数据 |
| `CUSTOMER_ADMIN` | 是 | 后台创建 | 客户管理员，可查看本客户全部用户的会话、消息和 Trace |
| `USER` | 是 | 邀请码注册或后台补建 | 客户普通用户，只能查看自己产生的会话、消息和 Trace |

## 数据范围规则

| 数据范围 | `SUPER_ADMIN` / `PLATFORM_ADMIN` | `CUSTOMER_ADMIN` | `USER` |
| --- | --- | --- | --- |
| RAG 历史会话 | 全平台，可继续按客户筛选 | 本客户全部用户 | 本人 |
| 会话消息明细 | 全平台 | 本客户全部用户 | 本人 |
| Agent Trace | 全平台 | 本客户 | 本人关联会话的 Trace |
| 知识库/文档列表 | 全平台 | 本客户 | 本客户 |

## 注册与开户流程

1. 超级管理员在后台创建客户。
2. 系统生成客户邀请码并在客户列表展示。
3. 客户成员在登录页进入“加入客户空间”，填写邀请码注册。
4. 后端根据邀请码找到客户并创建 `USER`，不再允许前端直接传 `customerId`。
5. 客户管理员和平台账号由超级管理员在“用户管理”中创建。
6. `CUSTOMER_ADMIN` 和 `USER` 必须绑定客户，`PLATFORM_ADMIN` 和 `SUPER_ADMIN` 的 `customerId` 为空。

## 为什么不让公开注册创建平台用户

平台用户具备跨客户或内部排障能力，一旦开放自助注册，就会和客户数据隔离模型冲突。邀请码只代表某个客户的加入凭证，不应该承担平台账号审批能力。
